# 08 — MEMORY ENDPOINTS

**Base path:** `/api/v1/memories`
**Module:** `MemoryModule`
**Table:** `Memory` (`id`, `ownerId`, `petId`, `type`, `title`, `description`, `imageUrl`, `createdAt`)

Memories are the user's history with their pet — the "memory book" screen. Some are
generated by the system (goal completions, milestones), others are written by the user.

---

## 1. Endpoints

| # | Method | Path | Scope | Description |
|---|--------|------|-------|-------------|
| 1 | `GET` | `/memories` | `[MVP]` | Paginated memory book |
| 2 | `POST` | `/memories` | `[MVP]` | Write a memory manually |
| 3 | `GET` | `/memories/:memoryId` | `[MVP]` | One memory |
| 4 | `PATCH` | `/memories/:memoryId` | `[MVP]` | Edit title/description |
| 5 | `DELETE` | `/memories/:memoryId` | `[MVP]` | Delete a memory |
| 6 | `POST` | `/memories/:memoryId/image` | `[MVP]` | Attach or replace the image |
| 7 | `POST` | `/memories/:memoryId/generate-description` | `[LATER]` | AI-written description |

---

## 2. Memory types

| `type` | Created by | Trigger |
|--------|-----------|---------|
| `goal_completed` | system | `POST /goals/:goalId/complete` |
| `pet_created` | system | `POST /pets` |
| `first_interaction` | system | first `POST /pets/:petId/interactions` |
| `milestone` | system | bonding / age thresholds |
| `snapshot` | user | user captures a moment from the world |
| `note` | user | free-form entry |

System types are created **inside the transaction of the action that caused them**,
never by a separate client call — that keeps the history trustworthy.

---

## 3. `GET /memories` `[MVP]`

Query params:

| Param | Type | Description |
|-------|------|-------------|
| `petId` | UUID | filter to one pet |
| `type` | string | repeatable |
| `hasImage` | boolean | only entries with an image |
| `from`, `to` | ISO date | date range |
| `limit`, `cursor`, `order` | — | see `00-conventions.md` §6 (`order` defaults to `desc`) |

`200`

```json
{
  "items": [
    {
      "id": "m-14",
      "petId": "9a1f...",
      "type": "goal_completed",
      "title": "Ran 5km",
      "description": "Blorb watched from the window and got a Moon Lamp out of it.",
      "imageUrl": "/uploads/memories/2026/08/8f2a-snapshot.webp",
      "createdAt": "2026-08-19T18:40:02.000Z"
    }
  ],
  "nextCursor": "m-09",
  "hasMore": true
}
```

`imageUrl` is a path served by the media package — PostgreSQL stores the path, never
the file (`techStack.md` — Storage).

---

## 4. `POST /memories` `[MVP]`

```json
{
  "petId": "9a1f...",
  "type": "snapshot",
  "title": "Blorb slept in the plant pot",
  "description": "For four hours. On purpose.",
  "imageUrl": "/uploads/memories/2026/08/8f2a-snapshot.webp"
}
```

| Field | Rules |
|-------|-------|
| `petId` | must belong to the user; optional for `note` |
| `type` | only `snapshot` or `note` — system types are rejected with `400 RESERVED_MEMORY_TYPE` |
| `title` | 1–120 chars |
| `description` | 0–2000 chars |
| `imageUrl` | must be a path previously returned by `POST /media/uploads` |

Two-step image flow: upload first (`09-media-endpoints.md`), then reference the
returned path here. Keeps this endpoint pure JSON.

`201` → the created memory.

---

## 5. `POST /memories/:memoryId/image` `[MVP]`

`multipart/form-data`, field `file`. Convenience wrapper that uploads and attaches in
one call for the "capture this moment" button, which produces a canvas snapshot the
client cannot pre-upload comfortably.

- Accepts `image/png`, `image/jpeg`, `image/webp`
- Max 5 MB
- Replaces any existing image; the old file is deleted from local storage

`200` → the updated memory. Errors: `413 PAYLOAD_TOO_LARGE`, `415 UNSUPPORTED_MEDIA_TYPE`.

---

## 6. `PATCH` / `DELETE` `[MVP]`

`PATCH` accepts `title` and `description` only — `type`, `petId` and `createdAt` are
immutable, so history cannot be rewritten into something that never happened.

`DELETE` returns `204` and removes the attached image file from local storage.

---

## 7. `POST /memories/:memoryId/generate-description` `[LATER]`

Optional AI enrichment (`project-overview.md` §11). Requirements when built:

- Never called automatically — always a user action.
- Must fail soft: if the AI service is down, return `503 AI_UNAVAILABLE` and leave the
  memory untouched. The application must work fully without it.
- The generated text is a **suggestion** returned to the client; it is only persisted
  when the user saves it through `PATCH /memories/:memoryId`.
